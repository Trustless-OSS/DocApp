# FAQ

Frequently asked questions about Trustless OSS.

## General

### What is Trustless OSS?
Trustless OSS is a platform for escrow-backed GitHub bounties built on the Stellar ecosystem. It enables secure, transparent payments for open source contributions while keeping GitHub as the primary workflow platform.

### How does it work?
1. **Fund**: Maintainers fund bounties with stablecoins
2. **Claim**: Contributors claim bounties on GitHub issues
3. **Work**: Contributors submit work via pull requests
4. **Verify**: Maintainers review and approve work
5. **Pay**: Funds release automatically from escrow

### Is it really trustless?
Yes! Funds are held in Stellar smart contracts that only release when predefined conditions are met. Neither party needs to trust the other - the code enforces the agreement.

## Bounties

### What types of bounties can I create?
- Bug fixes
- Feature development
- Documentation
- Security audits
- Performance improvements
- Translation/localization
- Design work

### What's the minimum bounty amount?
$10 USD equivalent in any supported stablecoin.

### What's the maximum bounty amount?
- Free tier: $1,000
- Pro tier: $10,000
- Enterprise: Custom limits

### How long do bounties last?
Bounties can have deadlines from 1 day to 1 year. Default is 30 days.

### Can I extend a bounty deadline?
Yes, you can extend deadlines up to 3 times, with a maximum total duration of 1 year.

### What happens if a bounty isn't completed?
If a bounty expires without completion:
1. The contributor's claim is released
2. The bounty becomes available for others to claim
3. You can choose to extend, cancel, or leave it open

## Payments

### What currencies are supported?
- USDC (Stellar)
- EURC (Stellar)
- BRLT (Stellar)
- USDT (Stellar)
- More coming soon

### How are payments processed?
Payments are processed through Stellar smart contracts:
1. Funds are locked in escrow
2. Smart contract verifies completion conditions
3. Funds automatically transfer to contributor's wallet
4. Transaction is recorded on the Stellar blockchain

### Are there any fees?
- **Free tier**: 5% platform fee (minimum $1)
- **Pro tier**: 3% platform fee
- **Enterprise**: Custom fee structure

### When do contributors get paid?
Immediately upon bounty completion and verification. Payments are processed within minutes.

### What about taxes?
We provide tax documentation (1099 forms for US contributors). Contributors are responsible for reporting income according to their local tax laws.

## Security

### How are funds secured?
Funds are held in multi-signature Stellar smart contracts that require:
1. Completion verification
2. Maintainer approval (optional)
3. Time-based releases for disputes

### Has the code been audited?
Yes, our smart contracts undergo regular third-party security audits. We also run a bug bounty program for security researchers.

### What happens if there's a dispute?
Dispute resolution process:
1. **48-hour cooling period** after completion claim
2. **Mediation** by Trustless OSS team (if requested)
3. **Arbitration** using decentralized oracle (if needed)
4. **Time-based release** after 7 days if no resolution

### Is my GitHub data safe?
We only request minimum required permissions:
- Read access to issues and pull requests
- Write access to add labels and comments
- No access to private repository code unless explicitly granted

## Troubleshooting

### GitHub App not appearing
1. Check you have admin permissions on the repository
2. Verify the app is installed on the organization
3. Try reinstalling the app

### Transaction failed
1. Check your wallet has sufficient balance for fees
2. Verify you're on the correct network (Mainnet vs Testnet)
3. Check Stellar network status

### Bounty not updating
1. Refresh the page
2. Check GitHub webhook deliveries
3. Contact support with bounty ID

### Payment not received
1. Verify the bounty was completed and approved
2. Check your wallet address is correct
3. View transaction on Stellar Explorer
4. Contact support with transaction hash

### API issues
1. Verify your API key is valid and has correct scopes
2. Check rate limits in response headers
3. Ensure you're using the correct API version
